# File-kind tool facts for the agent harness catalog

Research for [File-kind tool facts](https://github.com/Gharib89/skills/issues/351), part of the map [setup-harness: a Setup skill for the agent harness](https://github.com/Gharib89/skills/issues/333). Question: for the Catalog's remaining file kinds (Dockerfile, GitHub Actions and Azure Pipelines workflow YAML, Markdown), per role (`lint`, `format`), which vendor tools exist, their trust tier, one-file time, hook, cloud-passing install route and blocked routes, registry provenance and traps. Also: does any tool need a runtime the cloud image lacks, and does Azure Pipelines YAML have a vendor linter at all? This file gathers facts; the entry format and rules are those of [Per-stack catalog form](https://github.com/Gharib89/skills/issues/349) (file kinds take `lint` and `format` only, never `turn`; versions are picked at run time).

Measured 2026-09-27. Versions are the registry's latest that day, recorded only to date the facts (entries carry no pin). Timings come from one local 12-core Linux machine, three runs each on one real file (this repo's 214-line `claude-review.yml` and 221-line `CONTEXT.md`) or a small synthetic one (an 11-line two-stage Dockerfile, an 8-line broken workflow), never from a cloud VM, so treat them as lower bounds. Probe scripts stayed in the session scratchpad.

Terms: **tier** as in [Install-check procedure](https://github.com/Gharib89/skills/issues/340) (1 Anthropic-authored, 2 the tool's own vendor, none otherwise). **Cloud** facts build on [Web-session probe of cloud setup unknowns](https://github.com/Gharib89/skills/issues/342) (registries, apt, the Go proxy and public `git clone` pass; unattached GitHub release assets, `codeload.github.com` and `storage.googleapis.com` are blocked). **Rungs** are from [Rung budgets and how a run measures them](https://github.com/Gharib89/skills/issues/343): edit 5 s per file.

## Headline findings

1. **Azure Pipelines YAML has no offline vendor linter.** Microsoft's validation is server-side only: the web editor's Validate and the Preview API (`POST https://dev.azure.com/{org}/{project}/_apis/pipelines/{pipelineId}/preview`, "takes the same parameters as queuing a run", [Sprint 174 notes](https://learn.microsoft.com/azure/devops/release-notes/2020/sprint-174-update#azure-pipelines)), which needs an existing pipeline id, credentials and network. `az pipelines` offers create, list, show, run, update and delete, no validate ([docs](https://learn.microsoft.com/azure/devops/pipelines/get-started/manage-pipelines-with-azure-cli)). Microsoft's `azure-pipelines-language-server` (npm 0.9.3, Microsoft maintainers) is an LSP only, with no CLI mode and no Anthropic plugin. The file kind cannot be detected by content either: a pipeline's YAML path lives in the Azure DevOps definition, and `azure-pipelines.yml` is only the wizard's default name.
2. **Docker is in the cloud image, which reopens Docker-based routes, but image pulls are unprobed and one registry is likely blocked.** [Cloud environments, Installed tools](https://code.claude.com/docs/en/cloud-environments#installed-tools) lists "docker, dockerd, docker compose" and says the Trusted defaults "include Docker Hub and other common registries". Measured locally: Docker Hub blobs 307 to `production.cloudfront.docker.com`, while the allowlist names `production.cloudflare.docker.com`; `ghcr.io` blobs 307 to `pkg-containers.githubusercontent.com`, which is not on the list. So `ghcr.io` images (hadolint's `hadolint-docker` hook, zizmor's image) are likely blocked and Docker Hub images are plausible but unproven. This also bears on [Per-stack tool facts](https://github.com/Gharib89/skills/issues/348), whose ShellCheck vendor hook is Docker-only.
3. **hadolint, the Dockerfile linter, has no cloud-passing non-container route from its vendor.** Its release binaries are blocked; Hackage `hadolint-2.15.1` needs `base >=4.20.1` (GHC 9.10, `tested-with: GHC == 9.10.3`) while noble's apt `ghc` is 9.4.7 and the image ships no GHC; the PyPI wheels (`hadolint-py`, `hadolint-bin`) are third-party. The vendor route left is Docker Hub `hadolint/hadolint:<tag>` through the image's dockerd (0.26 to 0.36 s per file warm). Docker's own linter, `docker build --check` (Buildx 0.15+, Dockerfile frontend 1.8+, [build checks](https://docs.docker.com/build/checks/)), is the format vendor's tool but needs the same daemon and resolves every `FROM` image's metadata from its registry (1.7 s with an unpulled base; a missing tag fails the check).
4. **No vendor formats Dockerfiles.** Docker ships no formatter; Prettier has no Dockerfile parser (`No parser could be inferred`, exit 2, measured). The candidates found (`reteps/dockerfmt`, dprint's plugin) are not the format vendor's, so not trusted. The Dockerfile `format` role has no tool.
5. **GitHub publishes no workflow linter CLI.** Its `@actions/languageserver` and `@actions/workflow-parser` (npm, GitHub maintainers, SLSA provenance) are an LSP and a library, with no Anthropic plugin. The workflow linters are each their own vendor: actionlint (rhysd) for correctness, zizmor (zizmorcore) for security. Both take one file in under 0.05 s.
6. **zizmor must run `--offline` on the edit rung.** A `GH_TOKEN`/`GITHUB_TOKEN` in the environment switches it to online mode ([usage](https://docs.zizmor.sh/usage/)). The cloud sets both to the placeholder `proxy-injected` when the GitHub proxy authenticates ([cloud environments](https://code.claude.com/docs/en/cloud-environments)); locally, `GH_TOKEN=proxy-injected zizmor` fails fatally ("no audit was performed", `ref-confusion` could not list branches). Online with a real token costs 0.9 s cold, 0.64 s warm; offline 0.04 s. Its vendor hook lives in a separate repo, `zizmorcore/zizmor-pre-commit`; `zizmorcore/zizmor` has no `.pre-commit-hooks.yaml`.
7. **Every chosen tool has a vendor hook except Prettier and Docker's own check**, but several vendor hooks are container hooks. `hadolint/hadolint` (`hadolint-docker` on ghcr.io, `hadolint` system), `rhysd/actionlint` (`actionlint` golang, `actionlint-docker` on Docker Hub, `actionlint-system`), `zizmorcore/zizmor-pre-commit` (python), `adrienverge/yamllint` (python), `DavidAnson/markdownlint-cli2` (node, plus two Docker Hub hooks), `google/yamlfmt` (golang). None: `prettier/prettier`, `zizmorcore/zizmor`, `microsoft/azure-pipelines-language-server`.
8. **Registry provenance is uneven.** Attested: yamllint (PyPI, publisher `adrienverge/yamllint` `publish.yaml`), zizmor on crates.io only (Trusted Publishing from `zizmorcore/zizmor`), `@actions/*` (npm SLSA). Not attested: zizmor on PyPI (0 of 11 files for 1.30.1), markdownlint-cli2, markdownlint-cli, Prettier and `azure-pipelines-language-server` on npm, actionlint and yamlfmt on the Go proxy (sumdb only), mdformat on PyPI, and the Docker Hub images.
9. **No tool needs a runtime the cloud image lacks** except hadolint (container or GHC 9.10) and `docker build --check` (dockerd, present per the docs). actionlint and yamlfmt need Go (preinstalled, version undocumented; actionlint's `go.mod` says `go 1.25.0`, so an older Go fetches a toolchain through the proxy). markdownlint-cli2 needs Node >=22 (the cloud's default). zizmor ships manylinux_2_28 wheels.

## Cloud image and registries

From [Cloud environments](https://code.claude.com/docs/en/cloud-environments): the image has "docker, dockerd, docker compose", Go "with module support", Node 20, 21, 22 (22 on `PATH`) with a global `prettier`, and Python with uv. No GHC or cabal. No versions are documented (`check-tools` on the VM reports them), so the global `prettier` is an unpinned image copy: the harness runs its own pinned one.

Trusted-list hosts relevant here: `registry-1.docker.io`, `auth.docker.io`, `index.docker.io`, `production.cloudflare.docker.com`, `ghcr.io`, `mcr.microsoft.com`, `dev.azure.com`, `hackage.haskell.org`, `proxy.golang.org`, `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, `index.crates.io`. Not listed: `pkg-containers.githubusercontent.com` (ghcr.io blob redirect, measured) and `production.cloudfront.docker.com` (Docker Hub blob redirect as measured from this machine; the CDN may differ by region). A listed host is not proof of reach (web probe precedent), and none of the container pulls was probed.

## Dockerfile

**Signals.** pre-commit's `identify` tags a file `dockerfile` when its name or any dot-separated part of it is exactly `Dockerfile` or `Containerfile` (`Dockerfile.prod` and `api.Dockerfile` match; lowercase `dockerfile` does not), [identify.py](https://github.com/pre-commit/identify/blob/main/identify/identify.py).

**Tools.** Docker (tier 2 as the format's vendor) ships build checks in BuildKit: `docker build --check .` runs the rules "without producing a build output"; `# check=error=true` or `BUILDKIT_DOCKERFILE_CHECK=skip=...` tune it ([build checks](https://docs.docker.com/build/checks/)). Measured: exit 1 on warnings (3 on the synthetic file), and it loads base image metadata (`load metadata for docker.io/library/busybox`), 1.7 s for an unpulled base, 0.12 s once pulled; a nonexistent tag fails the run. hadolint (tier 2, its own vendor; Hackage author Lukas Martinelli) links ShellCheck as a library (`ShellCheck >=0.11.0 && <0.12` in `hadolint.cabal`), so it lints `RUN` shell without a `shellcheck` binary (SC2086 reported from the scratch image). Config: `.hadolint.yaml` in cwd, then XDG and home paths; `--failure-threshold` sets the failing severity ([README](https://github.com/hadolint/hadolint)). No formatter from any vendor (headline 4).

**Hooks.** `hadolint/hadolint`: `hadolint-docker` (`language: docker_image`, `ghcr.io/hadolint/hadolint`) and `hadolint` (`language: system`). With no binary route, the usable hook is `local` with `language: docker_image`, `entry: hadolint/hadolint:<tag> hadolint` on Docker Hub. `docker build --check` has no hook anywhere; `local`, `pass_filenames: false` or one call per file (`-f <file> .`).

**Install.** Blocked: hadolint release binaries (GitHub release assets). Not viable: `cabal install hadolint` (needs GHC 9.10; noble apt `ghc` is 9.4.7; `downloads.haskell.org`, where ghcup fetches GHC, is not on the Trusted list). Third-party, not trusted: PyPI `hadolint-py` (shenxianpeng, 2.15.1.2) and `hadolint-bin` (justin-yan/pybin, 2.15.1), npm `hadolint` (an unrelated Bitbucket project). Vendor-published images: Docker Hub `hadolint/hadolint` (tags `v2.15.1`, `-debian`, `-alpine`, 2026-07-31) and ghcr.io. Pin kind for an image: tag plus digest; Docker Hub `last_updated` serves the 7-day cooldown.

**Traps.** The `hadolint-docker` vendor hook pulls from ghcr.io (headline 2). `docker build --check` sends the build context and reaches every base image's registry, so a private base image needs registry credentials; a `# syntax=` line pulls a frontend image too. Both routes need a running dockerd, which the cloud docs list but which [Web-session probe of cloud setup unknowns](https://github.com/Gharib89/skills/issues/342) did not exercise.

## GitHub Actions workflow YAML

**Signals.** `.github/workflows/*.{yml,yaml}` (actionlint's hook `files: ^\.github/workflows/`); zizmor also reads `action.{yml,yaml}` anywhere, `.github/dependabot.{yml,yaml}` and `.pre-commit-{config,hooks}.{yml,yaml}` (its hook's `files` regex).

**Tools.** GitHub publishes no linter CLI (headline 5). actionlint 1.7.12 (tier 2, rhysd): with no argument it checks every workflow in the repo, with paths only those, `-` reads stdin; exit 0 clean, 1 findings, 2 bad option, 3 fatal ([usage](https://github.com/rhysd/actionlint/blob/main/docs/usage.md)). It runs `shellcheck` and `pyflakes` on `run:` scripts when found; `-shellcheck=` disables that. Measured on a broken workflow: unknown runner label, untrusted `github.event.pull_request.title` in a script, undefined `matrix.missing`, and SC2086 via the PATH `shellcheck`. zizmor 1.30.1 (tier 2, zizmorcore; PyPI owner woodruffw): security audits of workflows, action metadata, Dependabot and pre-commit configs; exit 0 clean, 1 error, 2 bad arguments, 3 no inputs, 11 to 14 by highest finding severity; `--fix` applies safe fixes in place; config `zizmor.yml` or `--config`/`ZIZMOR_CONFIG`; HTTP cache in `~/.cache/zizmor` ([usage](https://docs.zizmor.sh/usage/)). Measured offline on the broken workflow: `artipacked`, `excessive-permissions`, `template-injection`, `unpinned-uses`. Formatter: Prettier (YAML is a built-in language, [docs/index.md](https://github.com/prettier/prettier/blob/main/docs/index.md)); `yamlfmt` is the alternative.

**Hooks.** `rhysd/actionlint`: `actionlint` (`language: golang`, pre-commit >= 3.0.0), `actionlint-docker` (`docker.io/rhysd/actionlint:1.7.12`, bundles shellcheck and pyflakes per its Dockerfile), `actionlint-system`. `zizmorcore/zizmor-pre-commit`: `zizmor` (`language: python`, `require_serial: true`, `args: [--no-progress]`); add `--offline`. Prettier: `local`.

**Install.** actionlint: `go install github.com/rhysd/actionlint/cmd/actionlint@v1.7.12` through the Go proxy (`.info` Time serves the cooldown). Blocked: release binaries and `download-actionlint.bash` (fetches release assets), both listed as official in [install.md](https://github.com/rhysd/actionlint/blob/main/docs/install.md). Third-party, not trusted: PyPI `actionlint-py` (sdist only, Grzeliński and Rhee), npm `actionlint` (an unrelated 2022 package). zizmor: `uv tool install zizmor==1.30.1` (binary wheels for manylinux_2_28 and musllinux, `requires_python >=3.10`) or `cargo install --locked zizmor` (crates.io, attested, compile time unmeasured). Blocked: release binaries; the official `ghcr.io/zizmorcore/zizmor` image is likely blocked (headline 2). Prettier: npm.

**Traps.** actionlint results depend on whether `shellcheck` and `pyflakes` are on PATH, so pin both or disable them explicitly. Its runner-label list is compiled in; a new GitHub label or a self-hosted label needs a newer actionlint or `self-hosted-runner.labels` in `actionlint.yaml`. zizmor online mode is chosen by environment (headline 6) and online audits call the GitHub API, so the same file can give different findings online and offline. yamllint's default config fights workflow files: 35 findings on this repo's `claude-review.yml` (33 `line-length` at 80 columns, `truthy` on `on:`, `document-start`), so it is not a workflow default.

## Azure Pipelines YAML

**Signals.** Only the conventional name `azure-pipelines.yml` (the wizard default, [Azure DevOps Server 2020 notes](https://learn.microsoft.com/azure/devops/server/release-notes/azuredevops2020#pipelines)); templates and renamed pipelines are indistinguishable from other YAML without the definition in Azure DevOps.

**Tools.** No offline vendor linter (headline 1). Microsoft's options: the web editor's Validate (catches bad variable definitions and conditions, [YAML pipeline editor](https://learn.microsoft.com/azure/devops/pipelines/get-started/yaml-pipeline-editor#validate)); the Preview API with an optional `yamlOverride` (needs an existing pipeline and read access to every template repo); the org-specific schema via the Yamlschema Get REST API ([task reference FAQ](https://learn.microsoft.com/azure/devops/pipelines/tasks/reference/#faq)); `service-schema.json` in `microsoft/azure-pipelines-vscode` (1.6 MB, last changed 2025-09-25); and `azure-pipelines-language-server` 0.9.3 (a fork of Red Hat's YAML language server, validates against a schema, stdio mode, no CLI). Generic YAML syntax: yamllint (tier 2 for YAML, not Azure-aware). Formatter: Prettier (generic YAML).

**Hooks.** None from Microsoft. yamllint: `adrienverge/yamllint`.

**Install.** Preview API: `dev.azure.com` is on the Trusted list, but a cloud run has no Azure DevOps credential and the call is per pipeline id, so it is neither an edit-rung nor an offline check. yamllint: PyPI (attested) or apt 1.33.0.

**Traps.** Azure Pipelines YAML is template-expanded server-side (`${{ }}` compile-time expressions, `extends`, cross-repo templates), so any local check sees only the unexpanded file.

## Markdown

**Signals.** `*.md`, `*.markdown` (identify tags both `markdown`).

**Tools.** CommonMark has no linter. markdownlint-cli2 0.23.3 (tier 2, David Anson, author of the `markdownlint` library): config precedence `.markdownlint-cli2.{jsonc,yaml,cjs,mjs}`, then `.markdownlint.{jsonc,json,yaml,yml,cjs,mjs}`; `--fix` fixes in place; `#` or `!` negates a glob; `--no-globs` ignores config `globs` ([README](https://github.com/DavidAnson/markdownlint-cli2)). markdownlint-cli (igorshubovych, co-maintained by David Anson) is the older CLI; cli2 drops `.markdownlintrc` and `.markdownlintignore`. Formatter: Prettier (Markdown, GFM, MDX v1 built in). mdformat 1.0.0 (hukkin) is an alternative with a hook in `executablebooks/mdformat`; rumdl (rvben, 0.2.77, 0.x) is newer and not researched further.

**Hooks.** `DavidAnson/markdownlint-cli2`: `markdownlint-cli2` (`language: node`), `markdownlint-cli2-docker` and `markdownlint-cli2-rules-docker` (Docker Hub `davidanson/*:v0.23.3`). Prettier: `local` (`prettier/pre-commit` and `pre-commit/mirrors-prettier` archived, per [Per-stack tool facts](https://github.com/Gharib89/skills/issues/348)).

**Install.** npm (`engines.node >=22`); in a JS repo, the lockfile. Homebrew and Docker are the other vendor routes.

**Traps.** Prettier and markdownlint conflict by default (line length, list indent, emphasis style): markdownlint ships `style/prettier.json`, which "Disables rules that may conflict with Prettier", so an entry that pairs them must extend it. `markdownlint-cli2 .` "would lint every file in the current directory tree", so pass files or globs. MD013 (80 columns) fires on every long line: 62 issues on this repo's `CONTEXT.md` with the default config.

## Where evidence is thin

- **No container pull was probed in a cloud VM**: Docker Hub (`hadolint/hadolint`, `rhysd/actionlint`, `davidanson/markdownlint-cli2`, base images for `docker build --check`), ghcr.io, and whether dockerd actually runs in a session. The blob-redirect hosts come from this machine only.
- **Cloud image versions**: Buildx (build checks need 0.15+), Go (actionlint needs 1.25+ or a proxy toolchain fetch), Docker Engine.
- **No timing is from a cloud VM**; `go install` build time for actionlint and yamlfmt, and `cargo install zizmor` compile time, were not measured (no Go toolchain on this machine).
- Whether the cloud GitHub proxy makes zizmor's online mode work with the `proxy-injected` placeholder (it fails locally).
- Whether `azure-pipelines-language-server` bundles a default schema or needs the client to supply one, and whether an LSP diagnostics pull could serve as a lint command.
- Whether `docker build --check` needs the full build context or accepts a context-free invocation.
- How prek builds `language: golang` and `docker_image` hooks.
- mdformat, rumdl, yamlfmt and dprint were checked for registry and hook facts only, not timed or compared.
- No Anthropic-authored (tier 1) source recommending any of these tools was found; none of Anthropic's official plugins covers Dockerfile, YAML or Markdown (`gh api repos/anthropics/claude-plugins-official/contents/plugins`).
